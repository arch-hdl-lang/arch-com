# Independent SymbiYosys pipeline cross-check

`crosscheck_sby_pipeline.py` checks the archived generated SystemVerilog used by
`evidence/all_cycles_2026-11-21`, after verifying its SHA256 hashes. It does not
import `uf_pipeline`, `fma_uf_pipeline`, or `wrapper_uf_pipeline`, and does not
consume their SMT queries. Yosys parses the RTL and lowers the clocked processes;
SymbiYosys/yosys-smtbmc creates the time frames and induction obligations.
Arithmetic is concrete bit-vector RTL, not a replacement by sampled functions.
The independent toolchain still trusts Yosys, the solver, and this SV harness.
It is not an imported Lean certificate or a new IEEE arithmetic proof.

Run from the repository root (requires `yosys`, `sby`, `bitwuzla`):

```sh
python3 tests/fp_v1/synth/crosscheck_sby_pipeline.py --output tmp/sby-pipeline-check
# Select other archived configurations, or explicitly request all supplied fixtures (see the profile caveat below):
python3 tests/fp_v1/synth/crosscheck_sby_pipeline.py --output tmp/sby-pipeline-all --all
```

The default matrix contains FMA6/high reset, FMA7/low reset, and three-element
E2M1/high and E5M2/low block dots. It is a selected cross-check, not a claim that
all parameter configurations have been independently proved. Full-size concrete
arithmetic can require substantially more resources than the abstract checks.

Each baseline has four tasks:

* `startup`: unskipped BMC with depth latency + 3 (including assertion sampling),
  with reset on the first edge and arbitrary inputs/later resets.
* `induct`: unbounded k-induction of the same assertions. Short, insufficient
  induction attempts are skipped, which also skips early base-case checks in
  this task. **This task alone is not accepted as an all-cycles proof.** The
  separate unskipped `startup` must pass on the same design to discharge the
  entire base case. Both task hashes/statuses are recorded.
* `window`: arbitrary DUT register state and arbitrary resets, checking the
  output from the full interface latency onward. No initial reset is assumed.
  Only the observation monitor has initialized bookkeeping.
* `cover`: a witness for a filled pipeline, reset, and subsequent refill. This
  supplements the solver's assumption-consistency checks.

The output contract uses an independent queue of reference results (FMA) or
inputs to the combinational reference (block-dot), plus reset history. It
includes the output wrapper register. Every actual internal fill-valid bit is
observed and compared to the reset-history contract. Observations are additional
output wires only; DUT register updates are unchanged.

For block-dot induction, intermediate-stage assertions describe pairwise-tree
partial results and scale alignment from delayed inputs. They are generated
from the format, length, and balanced-tree specification, not from parsing RTL
update expressions. **They are asserted and proved, never assumed.** Register
names merely identify observation sites. Monitor age/fill invariants are also
proved. Both startup and induction must establish the strengthened property.

Six mutations per configuration alter the actual DUT RTL, leaving the reference
and contract fixed: a core register bypass (skew), an extra output register
(latency), inverted reset polarity, incorrect reset output value, a fill-valid
bit resetting to one, and premature output-valid gating. A mutation succeeds as
a negative control only with bounded `FAIL` and a VCD counterexample; an
induction `UNKNOWN`, timeout, or parser failure does not count.

Scope: archived FMA/block-dot configurations, synchronous reset, and internal
fill-valid behavior. No stalls, asynchronous reset, external ready/valid
protocol, compiler-wide correctness, or unrestricted parameter theorem is
claimed. The frozen manuscript and certificate campaign are untouched. The poster marks this follow-up with an asterisk.

## Runner regression checks

```sh
python3 tests/fp_v1/synth/test_sby_pipeline_replay.py
```

These solver-free checks bind the historical 32-element harness fingerprint,
reject corrupt fixtures and mutation-site drift, and ensure an empty matrix
or missing/unsuccessful mutation counterexample cannot be accepted.

## Replay without archived run outputs

Only five immutable fixture triples are shipped: `<key>.json`,
`<key>_comb.sv.gz`, and `<key>_staged.sv.gz` under
`evidence/all_cycles_2026-11-21/inputs/`. The JSON hashes bind the decompressed
SV consumed by the runner. Historical ARCH-input hashes in that metadata are
provenance only; the omitted `.arch.gz` files are not replay dependencies.
These fixtures are frozen compiler output, not generated by the current
checkout during replay. Arithmetic/reference correspondence and the original
compiler remain separate trust boundaries.

The runner generates every harness, mutation, SBY file and solver output anew.
No old status, log, SMT query, waveform, or receipt is read. Use new, nonexistent
output directories. Run these commands from the repository root:

```sh
python3 tests/fp_v1/synth/crosscheck_sby_pipeline.py --keys FMA6_high FMA7_low --timeout 90 --output /tmp/poster-fma
python3 tests/fp_v1/synth/crosscheck_sby_pipeline.py --keys e2m1_3_high e5m2_3_low --timeout 180 --output /tmp/poster-dot3
python3 tests/fp_v1/synth/crosscheck_sby_pipeline.py --keys e5m2_32_low --profile history --timeout 1800 --output /tmp/poster-dot32
```

Each invocation is sequential and exits nonzero unless every requested task
meets its expected result. Inspect the new `receipt.json`: `complete`, `passed`
and `all_cycles_proved` must all be true. Startup and induction must pass on
byte-identical designs. Every mutation must produce a bounded `FAIL`, exit
code 2 and a VCD counterexample. A timeout/UNKNOWN/error is never success.
`cover` must also pass, providing a reset/refill witness.

The default `strengthened` profile includes proved intermediate block-dot
assertions and monitor invariants. The explicit `history` profile reproduces
the original 32-element output/fill-valid harness, without those intermediate
assertions, and its original induction depth. They establish the same visible
output/fill-valid contract but are distinct proof problems. `--all` uses one
profile for all supplied inputs; it is not the historical mixed-profile replay.

Before publication pruning, all 50 generated design/configuration pairs were
compared to their original archived hashes and matched exactly when using
the historical timeouts. The commands above use 180 seconds for E2M1/3
instead of its historical 90 seconds; all generated design bytes are identical,
and this timeout line is its only SBY configuration difference. The
32-element replay retains the original 1800-second configuration exactly. The fresh replay is a separate run, not a relabeling of old
receipts. [POSTER_PROOF_RESULTS.md](POSTER_PROOF_RESULTS.md) records the
reference versions, coverage and numerical theorem scope. Logs and traces are
regenerated locally rather than committed.
