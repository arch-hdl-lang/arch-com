# ARCH v0.72.5

This is the first release containing the emitter fixes used by the GPT-5-mini
v51 benchmark compiler, source commit
`165841f187ae6c26349ee59b23b4b63bc8ecf60d`, now preserved by the annotated tag
[`benchmark-compiler-v51`](https://github.com/arch-hdl-lang/arch-com/tree/benchmark-compiler-v51).
That historical build still reported `arch 0.72.2`; it was not the official
v0.72.2 release asset. Historical generation provenance remains that source
commit and tag. Re-verification on a later release does not change which build
originally generated or repaired a candidate.

## Emitter fixes

- **`b3117381`: concatenation literal sizing.** Unsized ARCH numeric literals
  now retain their minimum-value width as explicit SV widths inside
  concatenations and replications, including pipeline concatenations. For
  example, `{0, x}` emits `{1'd0, x}`. Icarus rejects the former as an indefinite
  width; no candidate rewrite is required.
- **`165841f1`: arithmetic widening before zero-extension.** The pin commit is
  itself a codegen change. Widening addition, subtraction, and multiplication
  are evaluated at their ARCH result width before entering SV's self-determined
  `$unsigned` context. This preserves carries and product bits and distinguishes
  zero-extension of a signed bit pattern from sign-extension. Wrapping
  arithmetic retains its separate width rules.

Both changes have Icarus regression coverage. The concatenation fixture checks
an explicit leading zero (`{1'd0, x}`), mixed/nested literal widths, replication,
and values after simulation. The zero-extension fixture checks addition,
subtraction, unsigned and signed multiplication, wrapping arithmetic, and a
parameter override. Each fix is independently reversed in an isolated checkout:
its regression must fail, then pass when restored. The release retains v0.72.4's
shared-function state-localparam binding and CDC/RDC gate fixes.

## Agent tooling and documentation

These three historical commits shaped Lane A's MCP/advice behavior. They are
included to reproduce the tooling that ran the benchmark, **not as codegen
fixes**; they do not change SystemVerilog emission:

- **`ebc55ff5`** exposes sequential-block syntax in MCP reference lookup.
- **`130f46f8`** filters advice event kinds before top-K selection and retrieval
  accounting, avoiding starvation by ineligible events.
- **`8865eb92`** adds the optional `feature` argument to MCP advice retrieval.
  It defaults to false; callers explicitly choose feature descriptions or
  error/fix lessons.

The other two benchmark-only commits are **`94921396`**, aligning the language
specification/reference card with conditional syntax and FSM declaration scope,
and **`51105e16`**, improving the missing module closing-name diagnostic. The
parser/resolver diagnostics accompanying `b3117381` are also retained. These
help users and agents interpret syntax; they are separate from the two emitter
fixes above.

This accounts for all seven commits unique to the historical benchmark pin.
The two later commits on the preserved `codex/concat-literal-sizing` branch
(`fa5e7ae0` and `afbf6a33`) are outside this release's benchmark integration.

## Build provenance in `--version`

Git builds print semver and a 12-character source commit, for example
`arch 0.72.5 (git 0123456789ab)`. Staged or unstaged changes to tracked files add
`+dirty`; ignored build products and untracked files do not. Provenance is
captured at build time. A source archive without its own Git metadata reports
`git unknown` instead of borrowing an unrelated enclosing repository's commit.
Linked worktrees and detached release-tag builds are supported, and Cargo
rechecks tracked-file and Git-ref changes when rebuilding.

## Historical binary reproduction and replay

The archived binary hash is
`d081282bb149a2db15dfc532331f3437d00616114a8c79c1b774bacb4550cedd`.
A fresh locked offline release-profile build of the historical tag produced
`a3ba775ac551fca18e40066bd77ab0f2dd4276c433d95302fe6592150381398c`.
Both identify rustc 1.94.0; the original Cargo invocation and build flags were
not retained. The binary mismatch remains **unexplained**. All 20 selected
corpus designs emitted byte-identical SV in the two builds. The paper cites the
historical source commit/tag, not a claim of bit-for-bit binary reproducibility.

The separate benchmark reports record the v0.72.5 asset hashes, full-corpus
comparison against archived SV, and any selective harness replay. These release
notes do not claim replay results before that verification completes.
