# ARCH v0.74.2

A patch release that closes the residual checking gaps reported in #1074. Code
that relied on any of them now fails `arch check`.

## Checking changes

- **Two `seq` blocks driving one register are a multiple-driver error
  (#1102).** This holds even when both blocks use the same clock or mutually
  exclusive conditions; overlapping vector elements count as the same signal.
  Several assignments inside one block remain legal. Sequential blocks the
  compiler generates when lowering threads and TLM methods keep their
  intentional register-sharing exemption.
- **A declared `wire` must have a driver (#1102).** The driver can be a
  `comb`/`let` assignment or an instance output connection. An instance output
  may still bind a new net (`y -> result;`), but that no longer silently leaves
  a differently named declared wire undriven. Bus bundles are excluded from
  this whole-wire check.
- **Instance input expressions must resolve (#1102).** `a <- dinn;` with no
  `dinn` in scope is `undefined name`, instead of an implicit 1-bit net in the
  emitted SV. Bare `comb` targets have been resolved since 0.73.0 (#1080).

## Emitted SystemVerilog changes

- **Every generated file starts with `` `default_nettype none `` and ends with
  `` `default_nettype wire `` (#1102).** Any undeclared net that escapes the
  checker is now a hard error in downstream simulators, linters and synthesis.
  The trailing restore keeps hand-written files compiled after it unaffected.
